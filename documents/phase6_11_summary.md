## 0. このフェーズの動機と方針

フェーズ0〜5の結果、当初の3つの狙いは次の状態で止まっていた。

- ② 軌道再現で AD モデルを上回る → 否定(そもそも記述モデルと規範モデルを同じ軸で比べる設計が不利)
- ③ 準最適性の定量化 → 追跡回避ゲームが退化(能力が拮抗すると攻撃者は「真後ろへ逃げる」だけで
  捕捉を回避でき、捕捉可能集合が捕捉半径の近傍に縮む)。非対称 a_max でも実測の能力差では解消しない
- ① 捕捉可能集合による勝敗予測(AUC 0.745)→ 残っていたが、ランダム(0.5)としか比較していなかった

そこで方針を次のように切り替えた。

1. **評価軸を「軌道再現」から「勝敗予測」に変える**。単純なベースラインと比較する
2. **ゲームの目的を「捕まらない」から「守備者を抜く(ゴール方向に前進する)」に変える**(reach-avoid ゲーム)
3. **守備者の反応遅れを入れ、騙し合い(フェイント)を扱えるようにする**

実行環境はすべてローカル(Apple M5、idsse-data 7試合・1,454件)。各スクリプトは `PYTHONPATH=. uv run python scripts/phaseN_*.py` で再現できる。

## 1. フェーズ6: 対称追跡回避 HJI をベースラインと比較

スクリプト: `scripts/phase6_baseline_auc.py` / 結果: `phase6_baseline_auc_results.json`

| 予測スコア(ラベル: 次の保持チーム) | 全イベント AUC (n=1,447) | デュエル AUC (n=573) |
|---|---|---|
| 初期距離のみ | **0.752** | **0.671** |
| HJI の V(フェーズ3と同じ) | 0.745 | 0.659 |
| ベースライン8特徴量のロジスティック回帰(試合単位CV) | 0.789 | 0.745 |
| ベースライン + V | 0.789(Δ −0.001) | 0.745(Δ 0.000) |

- **フェーズ3の AUC 0.745 は「初期距離」とほぼ同じ情報だった**。退化した捕捉可能集合は、実質的に距離を言い換えているだけになっている。
- フェーズ3は V を「そのイベントの実際の長さ」で評価しており、後知恵の情報が混ざる懸念があった。固定3秒で評価しても AUC は同じ(0.745)で、実際には影響していなかった。
- デュエルの定義: 初期距離 8m 以下、かつ守備者が攻撃者よりゴール側にいる。

## 2. フェーズ7: 「守備者を抜く」reach-avoid ゲーム

実装: `ad_drg/reach_avoid.py` / スクリプト: `scripts/phase7_reach_avoid_auc.py` / 結果: `phase7_reach_avoid_auc_results.json`

**定式化**

- **座標系**: 初期時刻の攻撃者からゴールへ向かう方向を s 軸、その横を l 軸とする。相対状態は x = (s, l, v_s, v_l) の4次元のままで、ローカルで約18秒で解ける。
- **運動**: 藤村・杉原型の減衰付きダブルインテグレータ v̇ᵢ = uᵢ − vᵢ/τ(AD モデルと同じ構造)。τ = v_max/a_max ≈ 0.83 s。
  - 攻守で τ を共通にすると相対状態だけで閉じる。
  - 各選手の速度が a_max·τ 以下に自動で抑えられる。フェーズ0〜5のモデルには速度上限が入っていなかった。
- **ゲーム**: 攻撃者は捕捉半径 1.5 m に入らずに s ≥ s_pass に到達したい(抜きたい)。守備者はそれを阻止したい。
- **価値関数**: V ≤ 0 は「守備者がどう対応しても抜ける」を表す。V が大きいほど守備者が有利。

**新ラベル y_stopped**: 最初の3秒間に攻撃者が s ≥ s_pass に到達しなければ1(抜かれなかった)。トラッキングデータから直接判定する。

**結果**(守備者がゴール側にいるイベント n=1,173)

| | s_pass=1m | s_pass=0m |
|---|---|---|
| 実際に抜かれた割合 | 3.2% | 10.1% |
| 遅れなしで V ≤ 0(確実に抜ける)と判定された割合 | 1.2% | 3.3% |
| V 単体の AUC(y_stopped) | **0.856** | **0.851** |
| 初期相対状態のロジスティック回帰(CV) | 0.864 | 0.853 |
| ロジスティック回帰 + V | 0.867(Δ +0.003、有意でない) | 0.852 |

- **退化は解消した**。能力が同じでも、V は状態ごとに意味のある形で変化する。
- **対称追跡回避版より大幅に改善した**。「抜かれたか」を V 単体で AUC 0.85 前後で予測できる。対称追跡回避版の V は、向きをそろえても約 0.77 にとどまる。
- **ただし、初期相対状態をそのまま入れたロジスティック回帰と同等**で、上乗せはない。V は初期状態の滑らかな関数なので、線形モデルでもほぼ近似できてしまう。
- **旧ラベル(次の保持チーム)に対しては、V の予測力は初期距離と同程度**。旧ラベルは「ボールを奪ったか」に近く、主に距離で決まる。
- **理論上の構造的な帰結**: 能力が同じなら、ゴール側にいる守備者は相手の横の動きに合わせてついていけば止められる。そのため、理論上「確実に抜ける」状態はほとんどない。それでも実際には 3〜10% が抜かれている。
- 感度: s_pass(0 / 1m)、捕捉半径(1.0 / 1.5m)を変えても結論は同じ。

## 3. フェーズ8: 反応遅れ δ を入れた価値

実装: `ad_drg/reaction_delay.py` / スクリプト: `scripts/phase8_reaction_delay.py`、`scripts/phase8b_delay_sensitivity.py`

**モデル**: 最初の δ 秒間は、守備者が攻撃者の新しい動きに反応できない(加速度0で惰性走行)。その間、攻撃者は一定の加速度を自由に選ぶ。δ 秒後からは遅れなしのゲームを最適にプレーする。
「一度きりの遅れ(フェイントの瞬間)」という近似で、情報遅れが常に続くゲームを厳密に扱ったものではない。

**結果**(s_pass=0、全イベント)

| δ | 0 | 0.1 | **0.2** | 0.3 | 0.5 |
|---|---|---|---|---|---|
| 「確実に抜ける」判定の割合 | 3.3% | 5.5% | **10.3%** | 15.9% | 31.6% |
| 実際に抜かれた割合 | 10.1% | ← | ← | ← | ← |
| V_δ 単体の AUC | 0.851 | 0.842 | 0.828 | 0.807 | 0.750 |

- **判定割合が実測と一致する δ* は約 0.2 s**。s_pass やデュエルへの絞り込みを変えても 0.14〜0.20 s に収まった。
- **一律の δ は水準を合わせるだけで、順位付け(AUC)は改善しない**。どの局面で抜かれるかを当てる力は、遅れを大きくするほど下がる。
- **感度分析(8b、`phase8b_delay_sensitivity_results.json`)**: δ* とイベントのブートストラップによる95%CI(1,000回)

| 設定 | δ* [95%CI] |
|---|---|
| 主設定(a_max p95、攻守同等) | 0.197 s [0.163, 0.248] |
| **役割別の実測値(攻撃者 9.46 / 守備者 9.84 m/s²、フェーズ4b)** | **0.248 s [0.209, 0.286]** |
| a_max p50 / p99(攻守同等) | 0.187 / 0.208 s |
| v_max p50(τ 小)/ p99(τ 大) | 0.309 / 0.181 s |
| 守備者1.1倍 / 1.2倍 | 0.323 / 0.408 s |
| 攻撃者1.1倍 | 0.078 s |

  - a_max の水準を変えても δ* はほとんど動かない。
  - 攻守の能力比と τ(v_max)には敏感。つまり **δ* は運動能力の仮定とセットでしか決まらない**。
  - 実測の役割別能力を使った場合の δ* = 0.25 s は、フェーズ9でトラッキングから独立に推定した追随遅れの中央値 0.24 s とほぼ一致する。

## 4. フェーズ9: イベントごとの反応遅れをトラッキングから推定

スクリプト: `scripts/phase9_event_reaction_lag.py` / 結果: `phase9_event_reaction_lag_results.json`

**推定法**: ゴール座標系で、攻撃者の横速度に守備者の横速度が何秒遅れで追随しているかを、相互相関(遅れ 0〜0.8 s)で推定した。守備者が相手の横移動に合わせる「ミラーリング」の遅れにあたる。対象は858件。

- **推定遅れの中央値は 0.24 s**(四分位範囲 0.04〜0.48 s、最大相関の中央値 0.95)。モデルの δ* ≈ 0.2 s と独立した方法で整合した。**今回もっとも前向きな結果**。
- ただし、推定遅れで「抜かれたか」は説明できない。
  - 抜かれた局面の遅れの中央値は 0.16 s、抜かれなかった局面は 0.24 s。逆向きの傾向だが有意ではない(p=0.13)。
  - ベースラインに加えても改善しない(Δ −0.010)。
  - イベントごとの遅れを入れた V_{δᵢ} は、遅れなしの V より AUC が悪化した(0.742 → 0.652)。
  - 守備者ごとの平均遅れは折半信頼性がない(ρ = −0.28)。個人の特性として測れていない。

## 5. フェーズ10: 価値関数に基づく瞬間ごとの準最適性分解

スクリプト: `scripts/phase10_instantaneous_suboptimality.py` / 結果: `phase10_instantaneous_suboptimality_results.json`

**考え方**: 両者が最適に動けば、軌道に沿って V は変化しない。そこで、各フレームで各選手が最適からどれだけずれたかを、∇V と観測加速度から計算した。

- 攻撃者の損失率: L_a = p·u_a + a_max‖p‖ ≥ 0
- 守備者の損失率: L_d = a_max‖p‖ + p·u_d ≥ 0
- ここで p = ∇ᵥV。
- 正規化損失 ℓ = L / (2a_max‖p‖) ∈ [0, 1]。0 = 最適、0.5 = 無関係な方向、1 = 最悪方向。

フェーズ4で退化していた準最適性の指標を、退化しないゲームで作り直したものにあたる。

**初回版の見かけの結果に注意**: 「抜かれた時刻まで」の区間で積算した初回版では、ベースラインへの上乗せが ΔAUC +0.08 と大きく出た。しかし、これは次の2つの交絡による見かけの関係だった。

- 区間の長さ: 抜かれた時点で区間を打ち切るため、抜かれた局面ほど区間が短い。
- 勾配の大きさ: 損失は ‖∇V‖ に比例する。

そのため、次の予測設計に変更した。

**修正版の設計**: 最初の1秒間の振る舞いから、その後(1〜3秒)に抜かれるかを予測する(n=1,103、陽性73)。ベースラインは1秒時点の状態から作る。

| 追加した特徴量 | ΔAUC(ベースライン 0.916 に対して) |
|---|---|
| V(1秒時点) | +0.000 |
| 守備者の正規化損失 ℓ_d | −0.002 |
| 攻撃者の正規化損失 ℓ_a | −0.001 |
| フェイント候補(ℓ_a が高い直後 0.5 s 以内に ℓ_d が高い) | −0.001 |
| 1秒間の V の変化 | −0.001 |

- **振る舞いの特徴量に、状態を超える予測情報はない**。
- **選手ごとの折半信頼性**:
  - 正規化損失は ρ = 0.15(守備者)、0.18(攻撃者)で、いずれも有意ではない。
  - 正規化前の損失は ρ ≈ 0.6 と高い。ただし、これはその選手がよく置かれる状況(勾配の大きさ)を反映しているだけと考えられる。
- **正規化損失の平均値**: 守備者 0.49、攻撃者 0.41。守備者の加速度の向きは、理論上の最適方向とほぼ無関係になっている。
  - 25 fps の位置データを2回微分した加速度はノイズが大きく、これが主な原因の可能性が高い。
  - ローリングホライズン近似の粗さも一因と考えられる。

## 6. フェーズ11: 反応遅れ δ* の試合外検証

スクリプト: `scripts/phase11_delay_out_of_sample.py` / 結果: `phase11_delay_out_of_sample_results.json`

**目的**: δ* は「全体の抜かれ率に合わせた」値で、曲線は単調なので必ずどこかで一致する。それ自体は証拠にならない。
そこで δ を1つに固定したまま、局面タイプごとの抜かれ率の違いを試合外で予測できるかを検証した。

**手順**
- 6試合で δ* を決め、残り1試合で「確実に抜ける」を予測する(leave-one-match-out)。
- 初期状態の4変数(初期距離・接近速度・横ずれ |l0|・攻撃者の速さ)を、それぞれ三分位で3層に分けた計12層で、予測率と実測率を比べる。

**比較対象**
- N0: 全層に同じ率
- N1: 遅れなしの判定を定数倍して、全体の率だけ合わせたもの
- N2: 初期状態のロジスティック回帰

**事前に決めた判定基準**(実行前にスクリプトに記述)
- (i) 層ごとの誤差(MAE)で N0 と N1 の両方を下回る
- (ii) 層ごとの δ* の95%CI が全体の δ* を含まない層が 2 層以下

**結果(役割別の実測能力)**

| 予測 | 層ごとの MAE | 層間の相関(予測 vs 実測) |
|---|---|---|
| 遅れモデル M_delay | 0.0346 | 0.36 |
| N0 全層同じ率 | **0.0298** | −0.34 |
| N1 遅れなしを定数倍 | 0.0340 | 0.27 |
| N2 ロジスティック回帰 | 0.0080 | 0.98 |

- **(i) 不合格**: 遅れモデルは「全層に同じ率」にすら負けた。遅れなしを定数倍しただけのものとも差がない。
- **(ii) 不合格**: 全体の δ* = 0.248 s を含まない層が4層あった。層ごとの δ* は 0.12〜0.48 s とばらつく。
- 攻守同等の設定でも結論は同じ(MAE 0.0352、不合格)。
- **最大の食い違いは横ずれ |l0|**:
  - 攻撃者が守備者の正面にいる層(T1)で、モデルは「ほぼ抜けない」(2.9%)と予測するが、実際には最も多く抜かれている(15.1%)。
  - 横にずれている層では逆に、モデルが過大に予測する(16.8% vs 8.4%)。
  - 局面の幾何(正面か横か)と抜かれやすさの関係が、モデルと現実で逆になっている。
- 試合ごとに当てはめた δ* は 0.23〜0.27 s と安定している。ただしこれは全体の率が試合間で安定していることを示すだけで、仕組みの証拠にはならない。

**解釈**: δ* ≈ 0.25 s は全体の抜かれ率を合わせる1パラメータとして機能するだけで、局面ごとの違いは説明しない。
フェーズ9の追随遅れ(中央値 0.24 s)との一致は、偶然の可能性が高いと判断する。
正面の局面で実際に多く抜かれている理由として、次の2つが考えられる。
- **ラベルの問題**: 正面で接触・交錯すると、s=0 を横切ってもそれが「抜いた」とは限らない(タックルで倒れる、体を入れ替えるなど)。
- **目的の不一致**: 横にずれた局面では、攻撃者はそもそもこの守備者を抜こうとしていない(外を回る、パスを狙う)。

## 7. 総括

### 言えること

1. **ゲームの目的を「抜く」に直すと、退化は解消する**。価値関数 V は「抜かれるか」を単体で AUC 約 0.85 で予測する。追跡回避版は距離の言い換えにすぎなかった。
2. **遅れのない完全情報ゲームでは、ゴール側にいる守備者はほぼ抜かれない**(理論上確実に抜ける状態は 2.6〜3.3%)。一方、実際の抜かれ率は 10.1% で、モデルと現実の間に明確な差がある。

### 否定された・言えないこと

- **勝敗予測の上乗せ**: どのラベル・どの設計でも、V は初期状態の単純なロジスティック回帰を上回らなかった。
- **反応遅れによる説明(フェーズ11で否定)**: 一律の遅れ δ* ≈ 0.25 s は全体の率を合わせるだけで、局面ごとの違いは「全層同じ率」より悪い精度でしか予測できない。トラッキングの追随遅れ 0.24 s との一致も偶然と判断する。
- **騙し合いの検出**: 次のいずれも、状態を超える説明力も選手ごとの安定性も示さなかった。
  - イベントごとの遅れ(相互相関)
  - 瞬間ごとの準最適性
  - フェイント候補

### 次にやる価値があること(提案)

1. **モデルと現実の差がどこで生じるかを調べる**: フェーズ11で、横ずれに対する関係がモデルと現実で逆になっていることがわかった。これが最も具体的な手がかりである。
   - 正面の局面で「抜かれた」と判定された事例を動画・軌道で目視確認し、ラベルの誤判定(接触・交錯)か本当の突破かを確かめる。
   - 攻撃者が本当にこの守備者を抜こうとしている局面(進行方向が守備者に向かっている、など)に対象を絞る。
2. **ラベルの改善**: s=0 を横切るだけでなく、「抜いた後に一定距離以上離れる」「その後もボールを保持している」などの条件を加える。
3. **加速度ノイズの低減**: 準最適性とフェイント検出の否定的な結果は、2回微分のノイズが原因の可能性がある。平滑化を強める、加速度を使わず速度方向の変化で評価する、などで再評価する。
4. **データ量**: 7試合では陽性(抜かれた事例)が約120件しかなく、選手ごとの評価にも限界がある。より大規模なデータ(J1 等)での再検証が望ましい。

### 研究の位置づけについて

現時点で確かな貢献は、次の2点である。
- 追跡回避の定式化の退化を示し、reach-avoid 化でそれを解消したこと
- 差分ゲームの価値関数に、単純な状態特徴量を超える予測情報がないことを、きちんと管理した比較で示したこと

「騙し合いを捉える」という目標は、今回の枠組みではまだ達成できていない。
